# GPU development environment

This Pulumi project creates a disposable Ubuntu 24.04 GPU development machine
for `libcudf-rs`. It defaults to a `g7.4xlarge` in US East (N. Virginia)
(`us-east-1`) and uses the latest AWS Deep Learning Base OSS NVIDIA Driver GPU
AMI. The AMI supplies a G7-compatible NVIDIA driver and CUDA toolkits; cloud-init
selects CUDA 12.9 and installs GCC 13, Rust stable, GitHub CLI, and the remaining
project build tools.

The stack creates its own VPC, public subnet, encrypted 250 GiB root volume,
security group, and RSA SSH key. SSH is restricted to the public IPv4 address of
the laptop running `deploy.sh`.

## Deploy

You need Node.js, the AWS CLI, and the Pulumi CLI. Select the AWS SSO profile in
your shell rather than committing it to this directory:

```bash
cd dev-env
export AWS_PROFILE=<your-account-admin-profile>
./deploy.sh <stack-name> <region>
```

For example, `./deploy.sh dev` deploys in `us-east-1`, while
`./deploy.sh dev eu-south-2` selects Spain for an account where that opt-in
region is enabled. The program checks that the configured instance type is
offered in at least one Availability Zone in the selected region and chooses
one deterministically.

The deployment preflight also checks whether the selected region is enabled for
the account. Opt-in regions such as Spain must be enabled by an account
administrator before resources can be created there.

The helper logs into the selected SSO profile and exports its short-lived
credentials only into the deployment process. The profile name and credentials
are not placed in the Pulumi program or committed files.

The deployment writes the generated private key to `.ssh/<stack-name>.pem` with
mode `0600`. For Pulumi backends that need a passphrase, it also creates
`.ssh/<stack-name>.pulumi-passphrase`. That directory and stack-specific Pulumi
configuration files are gitignored. Keep both files safe: the private key is
generated by Pulumi and is also stored as an encrypted secret in the Pulumi
state. This environment is intended for disposable development use rather than
production.

It also maintains a clearly marked entry in `~/.ssh/config`, so the default
stack can be reached as `ssh libcudf-dev-dev`. A differently named stack uses
`ssh libcudf-dev-<stack-name>`. Destroying the stack removes only its marked SSH
configuration entry.

## Connect and test

```bash
./connect.sh <stack-name>
ssh libcudf-dev-<stack-name>
./sync-and-test.sh <stack-name>
```

`sync-and-test.sh` copies the current local checkout, including uncommitted
files, to `/home/ubuntu/libcudf-rs` without copying `.git`, local build output,
Pulumi dependencies, or SSH keys. It then runs `cargo test --workspace` on the
GPU machine.

If your public IP changes, update the allowlist and redeploy:

```bash
pulumi config set sshAllowedCidr "$(curl -fsS https://checkip.amazonaws.com | tr -d '[:space:]')/32"
pulumi up
```

Optional settings:

```bash
pulumi config set instanceType g7.4xlarge
pulumi config set rootVolumeSize 250
```

Destroy the machine when it is not in use (the helper also supplies the local
stack passphrase when the backend requires it):

```bash
./destroy.sh <stack-name>
```
